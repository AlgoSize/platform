What we can evidence

Compliance & release audit.

Map a repository against NIST SSDF v1.1 — 41 practices — and EU CRA Annex I Part II — 8 obligations. Coverage splits three ways and never collapses: what an analyzer measured, what a person signed for, and what this tool cannot see at all.

⚙

11 automated

An analyzer produced an artifact — an SBOM, a finding set, a run history — and the control is answered from it.

✍

7 attested

A named person signed a claim with an expiry date. Nothing was measured, and the page says so where the result is shown.

○

23 not covered

A fact about this tool, not a finding about you. Every one publishes the reason it cannot be evidenced.

Two axes, never one badge

how we know · and whether it holds

Three SSDF practices, each showing how the control is evidenced and, separately, what the evidence says.
Control Practice How we know Result
PW.4.1 Acquire and maintain well-secured software components from third parties ⚙ automated ✕ not met
PS.1.1 Store all forms of code based on the principle of least privilege ✍ attested ⏱ attestation expired
PW.8.2 Scope, design and perform executable code testing ○ not covered — no result · this tool reads code, it does not run it

A control can be automated and not met, or attested and expired. Collapsing those into one badge is how “we didn’t look” becomes “you passed” — so the two columns never merge, and a verdict can only ever be weakened on its way to the page, never strengthened.

How the fix gets made

The multi-model pipeline.

Cheap models filter, one expensive model fixes, and a different model grades the fix. That routing is the whole cost story.

  1. 1 Detect no model $0
  2. 2 Triage gpt-oss-20b $0.00022 / finding
  3. 3 Validate qwen3-30b-a3b-fp8 $0.000285 / finding
  4. 4 Fix kimi-k2.7-code $0.01225 / finding
  5. 5 Verify qwen3-30b-a3b-fp8 $0.000454 / finding

All five steps ≈ $0.00153 per finding — about $0.15 per 100 findings.

Blended across the funnel: triage sees every finding, deep validation about 15% of them, and the coding model about 10%. Estimates from list prices and assumed token volumes; every run reports what it actually spent.

Step 5 never uses the model from step 4 — the server rejects it (422 must_differ). A fix graded by its own author is not a cross-check, so the rule is enforced on the server, not in the dropdown.
